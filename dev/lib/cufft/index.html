cuFFT

cuFFT.jl offers NVIDIA's fast Fourier transforms at two levels:

  • The functions of AbstractFFTs.jl, which cuFFT.jl re-exports, work on CuArrays: fft, ifft, bfft, rfft, irfft, brfft, the in-place fft!, ifft! and bfft!, and the planning functions plan_fft etc. that return a reusable CuFFTPlan, or an AbstractFFTs.ScaledPlan wrapping one. cuFFT transforms Float16, Float32 and Float64 data and their complex versions; integer and rational inputs are converted to floating point first. Strided views are supported, and are copied when cuFFT cannot address them directly.
  • The generated bindings in libcufft.jl follow NVIDIA's C API, and change with the CUDA toolkit. A CuFFTPlan converts to the cufftHandle they take.
using CUDA, cuFFTx = CUDA.rand(ComplexF32, 1024, 64)p = plan_fft(x, 1)      # transform the first dimension, batched over the secondy = p * xp \ y ≈ x               # true

cuFFT.CuFFTPlan — Type
CuFFTPlan{T,S,K,inplace,N,R} <: AbstractFFTs.Plan{S}

A cuFFT plan, as returned by the AbstractFFTs planning functions (plan_fft, plan_rfft, plan_bfft!, ...) for CuArrays. Apply it with p * x or mul!(y, p, x), and invert it with inv(p) or p \ x; plan_ifft and inv(p) return an AbstractFFTs.ScaledPlan that wraps a CuFFTPlan. Plans are not constructed directly.

The type parameters describe the transform, so that methods can dispatch on them:

  • T: element type of the output;
  • S: element type of the input. Real-to-complex transforms have a real S and a complex T, complex-to-real ones the reverse;
  • K: the direction, cuFFT.CUFFT_FORWARD (-1) or cuFFT.CUFFT_INVERSE (+1). Real-to-complex transforms are forward, complex-to-real ones inverse;
  • inplace: whether the plan overwrites its input (true) or writes a separate output (false);
  • N: the number of dimensions of the arrays;
  • R: the number of dimensions that are transformed.

A plan can be applied to arrays of its input size and element type, including strided views, from several tasks at once, each using its own stream. It has to be used in the CUDA context it was created in. Its fields are not part of the API. The underlying cuFFT handle is returned to a cache when the plan is garbage collected, or earlier with CUDA.unsafe_free!(p), after which the plan cannot be used any more.
