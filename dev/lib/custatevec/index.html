cuStateVec

cuStateVec.jl wraps NVIDIA's cuStateVec library, part of cuQuantum, for simulating quantum circuits on state vectors. It has no integration with Base or LinearAlgebra functions; it offers two levels:

  • The functions and types documented below wrap cuStateVec's routines on a CuStateVec: applying gates, measuring, sampling, computing expectation values, accessing and reordering the elements, and the helper objects for distributed state vectors.
  • The generated bindings in libcustatevec.jl follow NVIDIA's C API, and change with the cuQuantum release. Use them together with handle.

The wrappers are named after the cuStateVec routine they call, in NVIDIA's camel case, without the custatevec prefix and with a ! when they modify their first argument: custatevecApplyMatrix is applyMatrix!, and custatevecComputeExpectation computeExpectation. Routines of a helper object also drop the object's name, which the type of their first argument gives, and getters drop Get: custatevecSamplerPreprocess is preprocess!, custatevecSamplerGetSquaredNorm squaredNorm, and custatevecInitializeStateVector initialize!. The exceptions are accessorGet and accessorSet!, which keep the object's name rather than shadowing get and set!, and swapParameters, which names the swap parameters that custatevecDistIndexBitSwapSchedulerGetParameters returns.

The wrappers share these conventions:

  • Qubits, or index bits, are numbered from 0: bit i of the index of a state vector's amplitudes is qubit i. Bit strings returned as integers have the first of the requested bits as their least significant bit.
  • Matrices are column-major, as Julia stores them, and can be in host or device memory.
  • Batched wrappers take one CuStateVec that holds n_svs state vectors of equal length one after the other.
  • Measurements take random numbers in [0, 1) from the caller, so that they can be reproduced. Flags such as adjoint, and the enums of the C API (custatevecCollapseOp_t, custatevecMatrixMapType_t, ...), are positional arguments.
  • The wrappers run on the task's stream. The ones that return host values, such as computeExpectation and abs2SumArray, wait for them.

cuStateVec.CuStateVec — Type
CuStateVec{T}(n_qubits; sv_type=CUSTATEVEC_STATE_VECTOR_TYPE_ZERO)
CuStateVec(data::CuVector{T})
CuStateVec(data::Vector{T})

A state vector with elements of type T, ComplexF32 or ComplexF64. The first form creates one of n_qubits qubits in the state selected by sv_type (see initialize!). The others take the amplitudes, whose number is a power of 2: a CuVector is used directly, a Vector is copied.

The amplitudes are in the field data, a CuVector{T}, and the number of qubits in nbits. Bit i (0-based) of the index of data is qubit i.

cuStateVec.CuStateVecAccessor — Type
CuStateVecAccessor(sv::CuStateVec, bit_ordering::Vector{Int}, mask_bit_string::Vector{Int},
                   mask_ordering::Vector{Int}; view=false)

An accessor that copies elements between the state vector and other buffers, with accessorGet and accessorSet!. The elements are numbered by the bit_ordering bits, the first being the least significant, among the elements whose mask_ordering bits have the values in mask_bit_string. With view = true, the accessor can only read.

Wraps custatevecAccessorDescriptor_t.

cuStateVec.abs2SumArray — Method
abs2SumArray(sv::CuStateVec, bitordering, maskBitString, maskOrdering) -> Vector{Float64}

The sums of the squared magnitudes of the elements of the state vector for each value of the bitordering bits (their probabilities, for a normalized state vector). The index of the result has the first of these bits as its least significant bit. Only the elements whose maskOrdering bits have the values in maskBitString are included.

Wraps custatevecAbs2SumArray.

abs2SumArrayBatched(sv::CuStateVec, n_svs, bitordering, maskBitStrings, maskOrdering)
    -> Vector{Float64}

Compute abs2SumArray for each of the n_svs state vectors that sv holds one after the other, with a mask bit string given as an integer in maskBitStrings for each. The results are concatenated.

Wraps custatevecAbs2SumArrayBatched.

source
cuStateVec.abs2SumOnZBasis — Method
abs2SumOnZBasis(sv::CuStateVec, basisInds) -> abs2sum0, abs2sum1

The sums of the squared magnitudes of the elements of the state vector for which the basisInds bits have even and odd parity. For a normalized state vector, these are the probabilities of measuring either parity on that Z product basis.

Wraps custatevecAbs2SumOnZBasis.

cuStateVec.applyGeneralizedPermutationMatrix! — Function
applyGeneralizedPermutationMatrix!(sv::CuStateVec, permutation, diagonals, adjoint::Bool,
                                   targets, controls, controlValues=ones(length(controls)))
    -> sv

Apply the generalized permutation matrix $DP$, or its adjoint, to the targets bits of the state vector, controlled by the controls bits having the controlValues. $P$ is given by the 0-based permutation and $D$ by its diagonals, both of length 2^length(targets), in host or device memory.

Wraps custatevecApplyGeneralizedPermutationMatrix.

             controlValues=ones(length(controls))) -> sv

Apply the gate matrix, or its adjoint, to the targets bits of the state vector, controlled by the controls bits having the controlValues. matrix is a Matrix or CuMatrix of size 2^length(targets), whose row and column indices have the first target as their least significant bit.

Wraps custatevecApplyMatrix.

cuStateVec.applyMatrixBatched! — Function
applyMatrixBatched!(sv::CuStateVec, n_svs, map_type::custatevecMatrixMapType_t,
                    matrix_inds, matrices, n_matrices, adjoint::Bool, targets, controls,
                    controlValues=ones(length(controls))) -> sv

Apply gate matrices to each of the n_svs state vectors that sv holds one after the other, as applyMatrix! does. matrices is a Vector or CuVector with the n_matrices matrices one after the other. cuStateVec.applySubSVOffset! — Method
applySubSVOffset!(sampler::CuStateVecSampler, sub_sv_ord, n_sub_svs, offset, norm)
    -> sampler

Treat the sampler's state vector as part of a larger one. It is the 0-based part sub_sv_ord of n_sub_svs parts, offset is the squared norm of the preceding parts, and norm that of all parts. The sampler must have been prepared with preprocess!; random numbers given to sample that fall outside this part are clamped to it.

Wraps custatevecSamplerApplySubSVOffset.

cuStateVec.handle()

The cuStateVec handle of the current task, for its active context and stream, for calling the C API of cuStateVec (cuStateVec.custatevec*) directly. It converts to a custatevecHandle_t. cuStateVec.migrate! — Method
migrate!(migrator::CuStateVecSubSVMigrator{T}, slice_index, src, dst, i_begin, i_end)
    -> migrator

Copy the elements [i_begin, i_end) (0-based) of the sub state vector src into the device slice slice_index, and/or those of the slice out to dst; with both, they are exchanged. src and dst are host vectors, or nothing, in memory the device can access (e.g. pinned with CUDACore.pin). cuStateVec.multiDeviceSwapIndexBits! — Method
multiDeviceSwapIndexBits!(sub_svs::Vector{<:CuStateVec}, devices::Vector{CuDevice},
                          indexBitSwaps::Vector{<:Pair}, maskBitString, maskOrdering,
                          device_network_type::custatevecDeviceNetworkType_t) -> sub_svs

Swap pairs of index bits of a state vector that is distributed over the sub state vectors sub_svs, which reside on the corresponding devices, one of which must be the current one. Their number is a power of two, and the global index bits that select the sub state vector follow the local ones. Only the elements whose maskOrdering bits have the values in maskBitString are swapped.

NVIDIA requires peer access to be enabled in both directions between all these devices (with CUDACore.enable_peer_access), and this crashes otherwise.

Wraps custatevecMultiDeviceSwapIndexBits.

cuStateVec.sample — Method
sample([rng,] sv::CuStateVec, sampled_bits, shot_count) -> Vector{Int64}
sample(sampler::CuStateVecSampler, sampled_bits, randnums;
       output=CUSTATEVEC_SAMPLER_OUTPUT_RANDNUM_ORDER) -> Vector{Int64}

Sample the values of the sampled_bits of the state vector, as integers whose least significant bit is the first sampled bit. The first form draws shot_count samples, with random numbers from rng (by default the task-local generator). The second one uses a sampler prepared with preprocess!, and a sample for each of the given random numbers in [0, 1); output selects whether the samples are returned in the order of the random numbers or in ascending order.

Wraps custatevecSamplerSample.
