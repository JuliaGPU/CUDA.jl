CUPTI.PCSamples — Type
CUPTI.PCSamples

PC samples collected by CUPTI.pc_sample:

  • reasons: the name of every stall reason, by CUPTI's index;
  • pcs: for every sampled PC, keyed by the CRC of its cubin (as computed by CUPTI.cubin_crc), its function's name and the offset of the PC in that function, the number of samples per stall reason index;
  • total: the number of samples, including dropped ones and samples in kernels that CUPTI doesn't report (e.g. in the driver);
  • dropped: the number of samples that were lost because CUPTI's buffers were full.

CUPTI.can_profile — Method
can_profile() -> Bool

Whether CUDA.jl should attempt to use CUPTI in the current process.

On Tegra, CUDA 10 through 12 require root, while CUDA 13 and later require read/write access to a profiling device node. This check is intentionally conservative because some CUPTI versions crash in cuptiSubscribe when that access is missing. On other systems, CUPTI reports permission errors normally, so this function returns true and lets CUPTI handle them.

CUPTI.pc_sample — Method
CUPTI.pc_sample(f; ctx=context(), period=14) -> CUPTI.PCSamples

Sample the PCs of warps executing kernels in ctx while executing f(), once every 2^period cycles on each SM. The caller should synchronize the context before and after f, as samples are only collected while sampling is active.

Warning

With CUPTI 13.2 and later, loading a module after PC sampling was disabled makes enabling PC sampling or the range profiler fail with CUPTI_ERROR_INVALID_OPERATION, even in other contexts. Call cuptiFinalize when CUPTI isn't in use anymore (e.g., after unsubscribing from callbacks) to avoid that.

source
CUPTI.profiler_params — Method
CUPTI.profiler_params(T, lastfield; fields...)

Construct a zero-initialized profiler API parameter struct of type T, setting the given fields. structSize covers the fields up to and including lastfield, which should be the last field the oldest supported CUPTI knows about: CUPTI appends fields to these structs, and rejects sizes it doesn't recognize.

source
CUPTI.range_profile — Method
CUPTI.range_profile(f, metrics::Vector{String}; ctx=context(), max_ranges=1024)

Collect metrics for every kernel launched in ctx while executing f(), and return a named tuple with a ranges × metrics matrix of values and the number of passes each kernel was replayed. Ranges are numbered in the order the kernels executed, which is serialized by CUPTI; at most max_ranges kernels are profiled.
