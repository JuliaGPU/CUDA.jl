cuTensorNet

cuTensorNet.jl wraps NVIDIA's cuTensorNet library, part of cuQuantum, for contracting and decomposing tensor networks and simulating quantum circuits. It has no integration with Base or LinearAlgebra functions; it offers two levels:

  • The functions and types documented below wrap cuTensorNet's routines and objects. They fall into three groups:
    • Network contractions: build a CuNetwork from input tensors, find a contraction path with rehearse_contraction, and contract it with contract!, optionally computing gradients with compute_gradients!.
    • Tensor decompositions: tensor_qr!, tensor_svd! and gate_split!, on CuArrays with mode labels or on cuTENSOR's CuTensors.
    • States: build a CuNetworkState by applying operators to it, then compute the state, its amplitudes, expectation values, marginals or samples, or project it on an MPS.
  • The generated bindings in libcutensornet.jl follow NVIDIA's C API, and change with the cuQuantum release. Use them together with handle.

The wrappers use snake-case names, and share these conventions:

  • Modes are labeled with integers (or, for the decompositions, characters). Modes with the same label are contracted. The modes of a state are numbered from 0, as in NVIDIA's API.
  • Objects keep the arrays they are given alive, and the library uses their memory directly: change their contents only where a function says that is supported.
  • Settings that NVIDIA exposes as attributes are passed as keyword structs (OptimizerConfig, SVDConfig, NetworkAutotunePreferences), or with attribute! and configure!, which take NVIDIA's attribute enums and values of the type NVIDIA documents for them. The same goes for the enum-typed keywords of the wrappers, such as algo of gate_split!.
  • Functions that launch work take a stream keyword, which defaults to the task's stream. The computations on states wait for their result; the others don't.

CuTensorNetwork, perform_contraction!, AutoTune, NoAutoTune and AutotunePreferences wrap NVIDIA's deprecated network descriptors and contraction plans, and are deprecated in favor of CuNetwork.

cuTensorNet.CuNetwork — Type
CuNetwork{T}()

An empty tensor network with elements of type T, to be contracted on the GPU. Add input tensors with append_tensor! and the output tensor with set_output!. Then find a contraction path with rehearse_contraction (or reuse one with set_optimizer_info!), allocate the workspace with prepare_contraction!, and contract the network with contract! as often as needed. The network keeps its tensors alive and uses their memory directly: their contents can change between contractions, but call purge_cache! when that of a constant input does.

net = CuNetwork{Float64}()append_tensor!(net, A, [1, 2])  # C[i,k] = A[i,j] B[j,k]append_tensor!(net, B, [2, 3])set_output!(net, C, [1, 3])rehearse_contraction(net, 2^30)prepare_contraction!(net)contract!(net)

Wraps cutensornetNetworkDescriptor_t, as created by cutensornetCreateNetwork.

source
cuTensorNet.CuNetworkOperator — Type
CuNetworkOperator{T}(extents)

An operator on a state with modes of the given extents, as a sum of terms that are added with append_product! and append_mpo!. Apply it to a CuNetworkState with apply!, or compute its expectation value with CuStateExpectation.

The tensors of an operator have the state modes they act on as their first modes, in order, followed by the corresponding dual modes. This differs from the layout of the operators that apply! takes.

Wraps cutensornetNetworkOperator_t.

source
cuTensorNet.CuNetworkState — Type
CuNetworkState{T}(extents; purity=CUTENSORNET_STATE_PURITY_PURE)

A quantum state, or other tensor network state, of modes with the given extents, starting as the vacuum state (all modes 0). Apply operators to it with apply! and the other apply_*! functions, or start from an MPS with initialize_mps!. Then compute the state itself with prepare! and compute!, or properties of it with CuStateAccessor, CuStateExpectation, CuStateMarginal, CuStateSampler and CuStateProjectionMPS. With purity = CUTENSORNET_STATE_PURITY_MIXED, it is a density matrix.

State modes are numbered from 0. The state keeps what it is given alive, but uses the memory of operators directly: register changes to an operator with update!. That memory must be device memory.

Wraps cutensornetState_t.

cuTensorNet.CuStateProjectionMPS — Method
CuStateProjectionMPS(state::CuNetworkState{T}, dual_tensors::Vector{<:CuArray{T}},
                     envs::Vector{<:Pair}; coefficient=1, symmetric=false, ortho=nothing,
                     boundary_condition=CUTENSORNET_BOUNDARY_CONDITION_OPEN)

A projection of the state on the MPS with the given dual tensors, for example to compress it or to optimize the MPS site by site. Each environment is given as lower => upper, the sites left and right of the MPS tensors it excludes, where -1 and length(dual_tensors) are the boundaries; it cannot span the whole MPS. ortho gives the orthogonality center of the MPS, if it has one, in the same form: 0 => 2 for site 1. Prepare it with prepare!, then use tensor_info, compute_env!, extract_tensor! and insert_tensor!.

Wraps cutensornetCreateStateProjectionMPS.

cuTensorNet.OptimizerConfig — Type
OptimizerConfig(; num_graph_partitions=8, graph_cutoff_size=8, ..., seed=0, ...)

Settings for the search for a contraction path by rehearse_contraction. Each keyword sets the CUTENSORNET_CONTRACTION_OPTIMIZER_CONFIG_* attribute with the corresponding name (e.g. graph_num_cuts sets GRAPH_NUM_CUTS, and num_graph_partitions GRAPH_NUM_PARTITIONS); see NVIDIA's documentation of these attributes. The defaults are those of the struct, which differ from NVIDIA's for some keywords, such as slicer_slice_factor and hyper_num_threads. hyper_num_samples > 0 makes the search try several paths, and seed makes it reproducible.

source
cuTensorNet.SVDConfig — Type
SVDConfig(; abs_cutoff=0.0, rel_cutoff=0.0,
          s_normalization=CUTENSORNET_TENSOR_SVD_NORMALIZATION_NONE,
          s_partition=CUTENSORNET_TENSOR_SVD_PARTITION_NONE)

Settings for the truncated SVD of tensor_svd! and gate_split!. Singular values below abs_cutoff, or below rel_cutoff times the largest one, are discarded. s_normalization (a cutensornetTensorSVDNormalization_t) normalizes the singular values that are kept, and s_partition (a cutensornetTensorSVDPartition_t) absorbs them into U, V or both.

cuTensorNet.append_tensor! — Method
append_tensor!(net::CuNetwork{T}, tensor::CuArray{T}, modes;
               conjugate=false, constant=false, requires_gradient=false) -> Int64

Add tensor as an input of the network, with an integer label for each of its modes, and return the id the network gives it. Modes with the same label are contracted. conjugate uses the complex conjugate of the tensor, constant promises that its contents don't change between contractions so that intermediate results can be cached, and requires_gradient makes compute_gradients! compute the gradient with respect to it.

cuTensorNet.apply! — Method
apply!(state::CuNetworkState{T}, modes, operator::CuArray{T};
       immutable=true, adjoint=false, unitary=false) -> Int64
apply!(state::CuNetworkState{T}, operator::CuNetworkOperator{T}; ...) -> Int64

Apply an operator to the state, and return its id. A tensor operator acts on the 0-based state modes, and has twice as many dimensions: its elements are stored following the rows of its textbook definition, i.e. as reshape(permutedims(M), ...) of a matrix M. immutable = false allows changing it later with update!, adjoint applies its adjoint instead, and unitary promises that it is unitary, which saves work.

Wraps cutensornetStateApplyTensorOperator and cutensornetStateApplyNetworkOperator.

cuTensorNet.compute! — Method
compute!(state::CuNetworkState; stream=stream()) -> (; tensors, extents, strides)
compute!(acc::CuStateAccessor, projected_values=[]; stream=stream()) -> amplitudes, norm
compute!(x::CuStateExpectation; stream=stream()) -> value, norm
compute!(x::CuStateMarginal, projected_values=[]; stream=stream()) -> marginal

Compute a prepared state, or a property of it, and wait for the result.

  • For a state, the result is the tensor of the full state, or the tensors of its MPS after finalize_mps!. MPS tensors can be truncated: the returned extents and strides say which part of each tensor holds the data. The full state can't be computed after apply_diagonal!. Wraps cutensornetStateCompute.
  • For an accessor, the amplitudes of the modes that are not projected, for the projected modes having the given values, and the squared norm of the state. Wraps cutensornetAccessorCompute.
  • For an expectation value, the expectation value of the operator, not divided by the squared norm of the state, which is also returned. Wraps cutensornetExpectationCompute.
  • For a marginal, the reduced density matrix of its modes (or its diagonal), for the projected modes having the given values. Wraps cutensornetMarginalCompute.

cuTensorNet.gate_split! — Method
gate_split!(A, modes_a, B, modes_b, G, modes_g, U, modes_u, S, V, modes_v;
            algo=CUTENSORNET_GATE_SPLIT_ALGO_DIRECT, svd_config=SVDConfig(), stream, ...)
    -> U, S, V, info
gate_split!(A::CuTensor, B::CuTensor, G::CuTensor, U::CuTensor, S, V::CuTensor; ...)

cuTensorNet.tensor_qr! — Method
tensor_qr!(A, modes_a, Q, modes_q, R, modes_r; stream, workspace_preference, memspace)
    -> Q, R
tensor_qr!(A::CuTensor, Q::CuTensor, R::CuTensor; ...) -> Q, R

Compute the QR decomposition of the tensor A, writing the factors to Q and R. The modes of A are split between Q and R by their labels: Q and R share one new mode, the modes of Q are rows and those of R are columns of the matrix being decomposed. Mode labels can be integers or characters. A is not modified.

Wraps cutensornetTensorQR. workspace_preference is a cutensornetWorksizePref_t, and memspace a cutensornetMemspace_t.

cuTensorNet.tensor_svd! — Method
tensor_svd!(A, modes_a, U, modes_u, S, V, modes_v; svd_config=SVDConfig(), stream, ...)
    -> U, S, V, info
tensor_svd!(A::CuTensor, U::CuTensor, S, V::CuTensor; ...) -> U, S, V, info

Compute the (truncated) singular value decomposition of the tensor A, writing the factors to U and V, and the singular values to the real vector S. The modes of A are split between U and V as in tensor_qr!. The truncation is configured with SVDConfig, and its result described by the returned CuTensorSVDInfo. When it reduces the shared mode, the factors are stored packed, as described at reduced_extent.

Wraps cutensornetTensorSVD.
